## Открытые пункты

- **DeepSeek API — на что годится** (2026-09-26, по ключу владельца) —
  проверка `GET /models` живым запросом (ключ `sk-863b95dd...`, полностью
  в scratchpad сессии, не в git) показала две модели, которых нет в
  обучающих данных: `deepseek-flash` (DeepSeek-V4.1-Flash — контекст
  1 048 576 токенов, до 393 216 на выход, вход текст+картинка, выход
  только текст, параметр `effort` low/high/max) и `deepseek-v4-pro`
  (DeepSeek-V4-Pro — тот же контекст/выход, вход только текст). API
  OpenAI-совместимый (`/chat/completions`), а также понимает формат
  Anthropic Messages — можно подключать как есть. Ключ валиден (авторизация
  проходит), но баланс счёта нулевой (`Insufficient Balance` на
  completions) — реальное качество генерации иврита с никудом проверить
  вживую НЕ удалось. **Вывод:** пока не выбор для генерации никуда (там
  решает только живая проверка `hebrew_spelling_rules.find_ktiv_chaser_
  violations`, см. [[feedback_hebrew_reader_workflow]] про Gemini) — можно
  рассмотреть после пополнения баланса и реального теста. Дешёвый/массовый
  вспомогательный трафик (черновой перевод, классификация, ресёрч по
  корпусу) — кандидат уже сейчас, риск невысокий. Отдельно поднят вопрос:
  заводить ли один постоянный (не в git) файл на диске под все API-ключи,
  чтобы не присылать их заново каждую сессию — не решено, ждёт ответа
  владельца.
- **Тексты израильских авторов без риска по авторским правам** (2026-09-26,
  по запросу владельца — ищем материал для фермы историй/растущих
  текстов). Израильское право (закон 2007, сверено по WIPO Lex): охрана
  длится жизнь автора + 70 лет, отсчёт с 1 января года, СЛЕДУЮЩЕГО за
  смертью. Проверены конкретные даты смерти: Бялик, Рахель (Блувштейн),
  Черниховский, Менделе Мохер Сфарим, Ахад ха-Ам — уже общественное
  достояние, можно брать. Двора Барон — станет общественным достоянием
  только с 1 января 2027, ПОКА нет (меньше четырёх месяцев). Левин Кипнис,
  Мирьям Ялан-Штекелис, Леа Гольдберг, Натан Альтерман, Агнон — при всей
  «классичности» этих имён ещё определённо НЕ в общественном достоянии,
  брать нельзя. Главный практический источник — Проект Бен-Иегуда
  (`benyehuda.org`, израильский аналог Project Gutenberg), тексты там явно
  помечены «נחלת הכלל» (общественное достояние), когда это подтверждено.
  **Практическая рекомендация:** оригинальный язык этих классиков обычно
  архаичнее и сложнее, чем нужно для градуированных читалок по уровням —
  использовать такие тексты не напрямую как материал для уровня, а как
  вдохновение для AI-пересказа (сюжет/герои) или как бонусный контент для
  продвинутого уровня (после ד), с собственной современной огласовкой и
  адаптацией через тот же пайплайн фермы.
- **Третий сайт: игра, где иврит расшифровывают, а не учат** (2026-09-26,
  идея владельца, не срочно). Образец — игры без слов вроде Chants of
  Sennaar: игрок попадает в мир с незнакомым языком, по картинкам и
  ситуациям догадывается, что значат надписи и реплики, и только так
  проходит дальше. В итоге он выучил язык, хотя ему ничего не объясняли.
  Идея: то же, но язык — настоящий иврит. Отдельный сайт рядом с читалкой
  и тренажёром (рабочее название «Play Hebrew» / «Play Read»), мини-игра,
  которая через прохождение учит базовым словам: предметы, действия,
  числа, цвета, «да/нет», приветствия. Что можно взять готовым: частотный
  список слов и озвучку из корпуса, картинки-мнемоники историй, FSRS для
  проверки, что слово действительно запомнилось. Не решено: жанр и объём
  (головоломки на одном экране или маленький мир), платформа (браузер,
  как оба сайта), сколько слов покрыть в первой версии, связь с читалкой
  (после игры — сразу первая книга уровня алеф).
- **Предложить добавить слово в повторение по частоте открытия перевода**
  (2026-09-26, идея владельца) — если пользователь открывает попап
  перевода одного и того же слова (по `lemma`) часто (порог обсудить —
  например 3-4 раза за сессию чтения книги или за N последних страниц),
  предложить: (1) добавить слово в «Мои слова»/повторение (FSRS), (2)
  добавить в тренажёр ВСЕ предложения книги, где встречалось это слово
  (не только текущее). Не с нуля: `markSeen(lemma)` уже есть
  (`reader-prototype.html`), но это одноразовый булев флаг ("видел
  хоть раз"), не счётчик — нужно завести отдельный счётчик открытий
  попапа per-lemma (localStorage, как и `seenCache`). Push предложения в
  тренажёр уже тоже есть — `window.cloudAddCustomCard(source, he, ru,
  focusWord)` (сейчас вызывается только при ручном ★, см.
  `saveVocabEntry`) — для "всех предложений книги с этим словом" его
  нужно вызвать в цикле по `data.sentences`, а не один раз.
  **Оценка нужности (не пере-инженерить):** сама идея сильная и дешёвая
  в реализации (счётчик + вызов уже существующей функции), НО есть два
  риска, из-за которых наивная версия была бы избыточной:
  (а) щёлкать по слову — не всегда "не помню перевод": иногда это
  любопытство к грамматике (корень/биньян/таблица форм), особенно в
  режиме `settings.detailed` — считать все клики как "не знает слово"
  ошибочно; (б) частые ГРАММАТИЧЕСКИЕ слова (предлоги вроде `לְ`, теперь
  у них есть отдельная карточка-парадигма, см. CHANGELOG v1.88.0/1.88.1)
  запросто наберут порог за пару страниц — если тогда закидывать в
  тренажёр КАЖДОЕ предложение с `לְ` из всей книги, это десятки
  однотипных карточек низкой ценности, а не помощь. **Вывод:** имеет
  смысл, но с ограничением — считать только для содержательных слов
  (`pos` ∈ сущ./прил./гл./нареч., не предлоги/местоимения/частицы —
  для них уже есть карточка-парадигма, отдельный механизм повторения),
  порог и окно подбирать по реальному использованию (первая версия —
  грубая эвристика, ожидаемо потребует перенастройки), предложение —
  ненавязчивый бейдж/подсказка, не модальное окно, прерывающее чтение.
- **Отзыв сам запоминает, где был пользователь** (2026-09-26, идея
  владельца). Суть: человек почти всегда пишет отзыв про то, что у него
  сейчас перед глазами («тут неверный перевод», «это слово с ошибкой»), но
  не указывает, где это «тут», и заставлять его это делать не надо. Из-за
  этого при разборе мы ищем слово или предложение по всем книгам. Решение:
  в момент отправки сайт сам прикладывает к комментарию место, где человек
  находится: книгу, страницу, предложение. Человек пишет как раньше, ничего
  дополнительно не делает; мы при разборе сразу открываем нужное место.
  Технически: сейчас `cloudSubmitFeedback` сохраняет только `type/text/app/
  url/uid/userAgent`, а `url` — адрес движка без книги. Добавить поле
  `context`: id и название книги, номер страницы/предложения (глава для
  эпоса), режим (чтение/fade/карточки), выделенное слово, если есть, версия
  сайта. Показывать его в `fetch_feedback.py` (в `E:\ivrit`) и в «Штабе
  Иврита». Для приватных книг (`?book=<url>`) сохранять только название,
  без URL. То же для тренажёра — см. его ROADMAP.

- **Архаичная форма `את`/`אתי`/`אתו` = "с"** (2026-09-24, из находки №2,
  вторая партия) — редкий (~15 случаев) омограф с `אֶת`-показателем
  прямого дополнения: буквы те же, различается только смыслом/огласовкой
  (например `אִתּוֹ` "с ним" vs `אֶת` перед прямым дополнением). Механически
  не фиксили — нужно смотреть перевод (`tr`) каждого случая отдельно,
  плюс отличать от совершенно другого слова `אַתָּה` ("ты") с теми же
  голыми буквами `אתה`. Мелкий, не блокирует.
