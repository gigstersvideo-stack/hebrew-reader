## Открытые пункты

- **[ВЫСОКИЙ ПРИОРИТЕТ] Вес читалки на телефоне: не тянуть всё, ограничить кэш**
  (2026-09-20, из обсуждения архитектуры) — мысль владельца: при открытии сайта
  на телефон, как кажется, грузится 58+ МБ и «все книги сразу»; это лишняя
  нагрузка на память, нужно ограничить объём или даже держать одну книгу.
  **Замеры (локальная копия, 2026-09-20):** открытие библиотеки ≈ 300 КБ
  (страница 234 КБ + манифест и рейтинг 70 КБ), куча JS ≈ 5–7 МБ; книги заранее
  НЕ загружаются — файл книги (0,2–1,7 МБ) грузится при открытии, озвучка по
  предложению (≈ 20 КБ), иллюстрации по страницам. Для масштаба (репозиторий,
  клиент это целиком не тянет): 37 файлов книг 17 МБ, 4567 mp3 158 МБ, 498
  картинок 300 МБ (JPEG 1024×1024 ≈ 0,6 МБ каждая).
  **Вероятная причина цифры 58 МБ:** `sw.js` кладёт в кэш КАЖДЫЙ загруженный GET
  (network-first + `cache.put`), без лимита и без вытеснения, поэтому кэш растёт с
  каждой прочитанной книгой: json + все прослушанные mp3 + картинки. Не
  подтверждено, откуда именно 58 МБ (передача в DevTools или Storage): замерить
  на телефоне; живой сайт из встроенного браузера Claude недоступен.
  **Что делать:** (1) вытеснение кэша: Workbox `ExpirationPlugin` (`maxEntries`,
  `maxAgeSeconds`, `purgeOnQuotaError`) или ручной LRU; держать в кэше только
  оболочку, текущую и последнюю книгу; (2) картинки: ≈ 640 px и WebP вместо
  1024 px JPEG (в 3–5 раз меньше); (3) проверить сжатие ответов (brotli) на
  Cloudflare Pages для json и html; (4) при необходимости кнопка «скачать книгу
  для офлайна» вместо неявного кэширования всего подряд.
- **Кнопка «назад»: осталось для оверлеев и тренажёра** (2026-09-20) — основная
  часть сделана в v1.84.0 (см. закрытые): экраны пишутся в историю. Осталось:
  (1) оверлеи (попап слова, ящик словаря, настройки, окно добавления книги) —
  на телефоне «назад» обычно закрывает их, а не выходит из книги; (2) то же
  проверить в тренажёре (экраны курса «Корни», теории, практики, растущих
  текстов); (3) `sw.js` при сбое сети на любой запрос (в том числе json) отдаёт
  оболочку, из-за чего вместо данных приходит HTML: отдавать её только для
  навигации (найдено при проверке; связано с пунктом про вес и кэш выше).
- **Словарная проверка полного написания в книгах: остаток** (2026-09-20) —
  надёжные классы сделаны (v1.83.0: 187 слов, 27 книг, 202 предложения
  переозвучены). Остаток: 173 слова (227 вхождений), из них около 42 слов
  автоматически исправимы, но в «ненадёжных» классах (лишний повтор буквы), и
  остальные — испорченные слова слабой модели и слова, которых словарь не
  знает (имена, заимствования, `בְּעוֹצָמָה`). Порядок как для тренажёра: сильная
  модель классифицирует слова (верно / исправить / переписать), результат
  проверять по словарю и глазами (она ошибалась в обе стороны). Запуск:
  `python hebrew_spelling_rules.py`-функции `find_dictionary_spelling_violations`
  (в аудит читалки словарная проверка пока не подключена).
- **Обновлять popularity.json по мере роста читателей** (2026-09-20) —

## Пусто — и это нормально

Если раздел выше пуст, значит либо всё сделано, либо ничего конкретного
ещё не предлагали — не значит, что писать сюда нечего в принципе.
