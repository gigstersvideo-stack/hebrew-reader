## Где что лежит

- **`books/<slug>/`** — одна папка на книгу (38 книг фермы + `demo-scifi`):
  `book-data.json`, `audio/`, `illustrations/`. Пути внутри `book-data.json`
  (`sentence.audio`, `sentence.illustration.img/imgMnemonic`) — относительные
  от корня сайта, вида `books/<slug>/audio/s1.mp3`.
- **`book-data-epic-ch01.json` … `ch20.json` — ИСКЛЮЧЕНИЕ, НЕ трогать
  структуру.** Сериал «Ярем: Рубеж» намеренно оставлен плоским в корне —
  на эти точные имена файлов завязан активный ежедневный инструмент
  разметки слов (`E:\NEW BIG PROJ\epic\tools\{mark_words,build_bookdata,
  merge_words}.py`, работает по 20-30 запросов/день к Gemini). Если когда-то
  решите перенести их в `books/epic-rubezh/chNN/` — сначала обновить все три
  скрипта в `epic/tools/`, иначе разметка молча перестанет находить файлы.
- **`books-manifest.json`** — поле `file` у каждой книги указывает на новый
  путь (`books/<slug>/book-data.json`); у `epic-rubezh-chNN` — по-прежнему
  на плоский `book-data-epic-chNN.json`.
- **`tools/`** — пайплайн генерации книг (`2_generate_story.py`,
  `3_generate_audio.py`, `5_gemini_pipeline.py`, `illustrate_book.py`,
  `niqud_fixes.py` — последний импортируется тремя остальными, должен жить
  рядом с ними). Раньше лежали в корне репозитория — README.md уже обновлён
  под новые пути (`python tools/2_generate_story.py ...`).
- **Код, который знает про структуру книг** (при следующей миграции путей
  проверить оба места):
  - `sw.js` → `BOOK_URL_RE` — определяет id книги по URL для эвикшена кэша
    (сейчас `/books/<slug>/...`).
  - `audit_corpus.py` → `audit_all_content()` и `audit_tts_known_bad()` —
    сканируют `books/*/book-data.json` + отдельно `book-data-epic-*.json`
    (эпос особо, см. выше).
- **`_archive/`** — неактуальное (сейчас: старый одноразовый
  `publish_pending.py` под конкретную партию книг).

## Рабочие правила (напоминание, не только про структуру)

- **Коммит и пуш — только по явной команде владельца**, не автоматически
  (подтверждено многократно, см. память проекта). Не `git add -A` — только
  конкретные файлы.
- В репозитории параллельно работают другие Claude-сессии (ктив мале/
  словарные фиксы, идеи в `ROADMAP.md`). Перед операциями, трогающими много
  файлов разом — `git status --short`; если что-то чужое не закоммичено,
  не трогать эти файлы и не наступать на них.
- Рабочая (не-git) папка фермы контента — `E:\NEW BIG PROJ` (свой
  `CLAUDE.md` там же); публикация книги — копирование `books/<id>/` сюда
  + запись в `books-manifest.json`.
